## Done on this branch
- **Slice 1:** permission rules in the language.
  - Grammar: agent `allow`/`ask`/`deny` and `settings { default-mode }`.
  - A typed `SettingsDef`, and `parsePermissionRule()`.
  - Checks V130-V135. These are the spec's V134-V139, renumbered +4 if integrate/sp merges first.
  - Rule strings round-trip byte for byte.
- **S-38 and S-50:** `code-review.at` and `scheduled-monitor.at` no longer deny their own reporter's `Write` ("Edit rules apply to all built-in tools that edit files").
- **Slice 2:** scaffold of agent rules on claude-code.
  - An agent `deny`/`ask` on a non-Bash tool becomes a frontmatter PreToolUse hook. It runs a generated check script with no `if:` and blocks on failure.
  - An agent `allow` is refused.
  - `default-mode` is written, and `auto`/`bypassPermissions` are refused.
- **An agent `deny`/`ask` on Bash is refused** ("use settings { deny }: an agent hook can't parse bash safely"). Three adversarial reviews showed that a hook which re-implements bash's tokenizer fails open. Inputs that passed a deny on `Bash(rm *)`:
  1. ``cat <<EOF\n'\nEOF\nrm x #'``
  2. ``cat <<EOF\n"\nEOF\nrm x #"``
  3. ``cat <<'EOF'\nit's fine\nEOF\nrm x # don't``
  4. ``echo $'\'' ; rm x #'``
  5. ``echo $'it\'s' && rm x # isn't``
  6. ``echo ${x:- #}; rm x``
  7. ``echo "${x:-a}" ${y:- # }; rm x``
  - Earlier rounds also found: fd-numbered redirects (`2>&1`), quoted assignment prefixes, other spellings and indirect runs.
- **S-51:** an agent `Edit` deny warns that Write, MultiEdit and NotebookEdit are not blocked by it.
- **T6, settings.json rule ownership (S-37, S-48).**
  - The manifest records the rules scaffold added. A re-scaffold removes owned rules the .at dropped, and prints each one. A hand-written rule is never removed.
  - Holds: a rule another topology declares; same-basename manifests (`sourcePath`, `ownershipSharedWith`); broken neighbour manifests.
  - A rule is removed only when settings.json round-trips byte for byte.
  - The interim manifest is written before settings.json.
  - Prune never deletes settings.json.
