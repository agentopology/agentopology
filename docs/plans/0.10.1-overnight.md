## N44a: session agents, grammar and validate (0.10.1)

What ships:
1. `runs: session | subagent` on `agent` (default `subagent`), and `place: <identifier>`.
2. One name everywhere. A session agent's id is its agent file name, its session name (`claude -n <id>`), its SendMessage address, and what talk edges point at. Validate fails a session agent id that isn't kebab-case.
3. Who may talk = flow edges between two session agents. Shorthand inside `flow`:
   - `talk: all` expands to an edge each way between every pair of session agents.
   - `talk: hub <name>` expands to `<name> <-> x` for every other session agent.
   - Expansion happens in the parser. `export --format json` shows the plain edges.
   - `[message: ticket | report | ask]` on an edge, in the same bracket style as `[when ...]`, records what crosses.
   - Header pattern `hub` is checked: with `: [hub]`, every session-to-session edge must touch one node; otherwise a warning names the edge.
4. With no talk edges among session agents, validate prints the warning `talk not declared: unguarded`.
5. `decides: [<decision>, ...]` on an agent (a human's seat). Validate warns when two agents claim the same decision. A gate or human `description` can't declare decisions, so the "no seat" check only covers decision names listed in a topology-level `decisions: [...]` field. Add that field: each entry with no agent claiming it is a warning.
6. T-03 (in this lane): an agent with `runs: session` and `background: true`, `skills:` or `permissions:` gets one warning per field, "ignored when run as a session". Done when: the fixture plus a planted variant shows exactly the expected warnings.
7. L-1 (in this lane): `permission-mode: default | acceptEdits | plan | bypassPermissions | auto` on a session agent. Validate warns on a talk edge whose two ends declare different modes: "a session in another permission mode holds incoming messages for its user, so this edge may not arrive".
8. Docs: `agentopology docs agent` lists the new fields, and the `flow` topic covers talk and `[message:]`. Add the rule numbers to spec/ and keep `spec-sync.test.ts` green (new rules continue the V-number sequence).
9. `src/import/serializer.ts` round-trips the new fields (parse → serialize → parse is equal).

Done when: the fixture validates with the warnings expected and no errors. Planted files fail as described: a duplicate decision, an edge breaking hub, a session agent with background, and differing permission modes.

## T-01: honest version (0.10.1)

`src/conformance/claude-code.ts` pins VERIFIED_ON. Read the installed version from `claude --version` (first x.y.z in stdout, 3 s timeout).
- `validate` and `guard --check` print `installed X: unverified` when X differs from VERIFIED_ON, and no `guard --check` line reads "refuse" without that mark.
- With VERIFIED_ON installed, the output is unchanged.
- With no `claude` on PATH, they print `Claude Code not installed`, and the exit code is unchanged.

Done when: tests with a fake `claude` on PATH printing 2.1.999, one printing VERIFIED_ON, and an empty PATH.

## N43 + T-02: the import check tells the truth (0.10.1)

`import x from "./f.at"` is resolved at validate time, relative to the importing file:
- a missing file is an error (V8, today an empty placeholder at `src/parser/validator.ts:504`), with exit 1;
- the imported file is parsed and its errors are reported under its path;
- a `sha256` that doesn't match is an error;
- an import cycle is an error.
Validate called on a string with no file path skips resolution and prints `imports not checked`.

Done when: planted missing file, bad sha, cycle, and a good import (the fixture imports a tiny file).

## N44b: session agents, binding, guards and launcher (0.10.1, after N44a)

1. Scaffold (claude-code) writes `.claude/agents/<id>.md` for a session agent, as for any agent, plus one start line per session agent in `.claude/sessions.md`: `claude --agent <id> -n <id>` (add `--permission-mode <m>` when declared).
2. Herdr launcher: `scripts/start-sessions.sh` is generated. It runs `herdr tab create <place>` per place, `herdr pane split` per extra session, and `herdr pane run <pane> "<start line>"`. If `herdr` isn't on PATH, it prints the start lines instead. Keep it a plain POSIX script.
3. Spawn guard: a PreToolUse hook on the Agent tool (matcher `Agent|Task`) with `onFailure: "block"` refuses when `subagent_type` names a `runs: session` agent. Exit 2, with a stderr reason.
4. Talk guard: when talk edges are declared, a PreToolUse hook on `SendMessage` refuses (exit 2) a send whose `to` isn't an edge from the current session. The current session's name comes from `$CLAUDE_SESSION_NAME` when set, else from the `-n` name recorded at start, else fail closed with the reason "session name unknown". It is fail-closed on any parse error.
5. T-04:
   - (a) `guard --check` prints one bypass line under every talk guard: "a send through a terminal command, a shared file or a session outside this repo is not seen".
   - (b) The guard appends one JSON line per send (from, to, allowed|refused, ISO time) to `.claude/state/talk.jsonl`.
   - (c) Validate warns when an agent with `decides:` has an incoming talk edge: "a decision can arrive here as a message"; that agent's guard refuses a message containing the word `approve` or `yes` addressed to it from another session. Keep it simple and documented as a heuristic.
6. `guard --check` grades the talk and spawn guards `unverified` (not `refuse`) unless VERIFIED_ON's conformance facts mark PreToolUse on SendMessage / Agent as proven. Add a field for it in `src/conformance/claude-code.ts`, set to false.
7. Other targets (codex, cursor, claude-workflow): validate and draw, and print "session agents: experimental, not compiled".

Done when:
- `scaffold --dry-run` on the fixture lists 4 agent files, `.claude/sessions.md` with 4 start lines, the launcher and both guards.
- A planted send from lane-video to lane-text gets exit 2 with a talk.jsonl line.
- A send from lane-video to lane-manager gets exit 0 with a line.
- A planted Agent call with subagent_type lane-manager gets exit 2.
- `guard --check` output for every examples/ file is unchanged except for files with session agents.

## VZ-2: the visualizer projection (0.11, starts now: visualizer only)

- `project(ast, facts)` in `src/visualizer/project.ts` is a pure function from the AST to the page data. One row per node kind in a rules table; an unknown kind draws with the default rule.
- The zero-drop test: for every field present on a parsed node, the page data either carries it or the rules table claims it as intentionally dropped. It passes on kitchen-sink.at and all examples, and fails on a planted unclaimed field.
- The page output for every example is visually equivalent: the same node ids and edges in the data.

## 0.11 grammar lane: T-10, T-07, T-06 (+L-2), T-09 (after the T-02 lane)

Build them in this order, one commit each:
- **T-10** `owner: <agent>` on a store. Two agents writing an owned store is an error naming both, unless one of them is the owner.
- **T-07** a top-level `machines { machine mac { os: macos } ... }` block; `machine:` on session agents, schedule jobs and stores. An unknown machine is an error. Validate errors on a home-folder absolute path (`/Users/<x>/`, `/home/<x>/`, `C:\\Users\\`) in any hook, gate, tool or action command.
- **T-06** a schedule `job` takes `carrier: session | cron | launchd | cloud | calendar` and `survives: pane-close | reboot | away`. L-2: `carrier: session` with any `survives:` beyond none is an error ("a session cron dies with its session and after 7 days"). `inventory` lists launchd plists and crontab lines whose command points into the project dir.
- **T-09** a `person <id> { away: "YYYY-MM-DD..YYYY-MM-DD" }` block. `human` takes `who: <person>`. Validate lists every step that waits on a person whose away window includes today or later, with its timeout behavior. A human may declare `valid: "YYYY-MM-DD..YYYY-MM-DD"`, and `step check` refuses a step guarded by that human after the window.
