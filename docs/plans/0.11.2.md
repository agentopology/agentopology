# 0.11.2 plan: two fixes, nothing else

## Fix 1: permission rules the .at wrote are owned through the manifest

- Premise: `deepMergeSettingsJson` (src/scaffold/merge.ts) unions `permissions.allow/ask/deny`
  with the file on disk, so a rule removed from the .at stays in `.claude/settings.json`.
- Record: the manifest entry of a settings file gains `permissions: { allow?, ask?, deny? }`,
  the rule strings this topology wrote and owns. The field is optional; there is no manifest version.
- Merge: an owned rule the .at no longer generates is removed; a rule never written by the .at
  (the user's) is kept; a rule the .at still declares stays once. A rule moved from allow to deny
  leaves allow and joins deny.
- A rule already in the user's file before the .at first wrote it stays the user's (not owned).
- Upgrade: a manifest entry without the record (0.11.1 and earlier) counts as owning exactly
  what the .at generates now, so the first re-scaffold after the upgrade removes nothing.
- Scope: the scaffold writes rules only to `.claude/settings.json` (never settings.local.json).
  The Codex `.rules` file is a whole generated file, rewritten from the .at or kept as a conflict
  when edited; it has no union merge, so it needs no change.

## Fix 2: an honest warning on a Codex allow rule

  Codex runs the command outside the sandbox without prompting, citing
