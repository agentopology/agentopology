# 0.11.2: name the rules the .at does not declare (warn only)

Problem: 0.11.x merges permission rules into `.claude/settings.json` as a union. A rule removed
from the .at stays in effect, and nothing says so. An invalid settings.json stops scaffold with a
stack trace.

What changes:
1. settings.json is written exactly as 0.11.1 writes it. Nothing is removed, rewritten or reordered.
2. `scaffold` and `guard --target claude-code` call one shared function that lists each allow, ask
   and deny rule in `.claude/settings.json` that the .at does not declare in the same list, and
   prints one line per rule.
3. Printed once per change: the manifest entry of `.claude/settings.json` stores the set last named
   (`undeclaredRulesNamed`, optional). The lines print only when the set gains a rule; the stored
   set is then replaced. An empty set prints nothing and clears the field. A missing, unparsable or
   malformed manifest counts as an empty stored set.
4. `--dry-run` prints the same lines and writes nothing, the manifest included.
5. An invalid settings.json: one line naming the file and the parse message, exit 1, nothing written.
6. The Codex allow warning (CX13-allow) stays as it is.

Not in 0.11.2: removing the rules the .at wrote (planned for 0.12).

Tests first, in their own commit: execution tests with the built CLI in temp dirs (the cases a-h of
the brief), then the fix. No change to the guard generator or to deepMergeSettingsJson.
